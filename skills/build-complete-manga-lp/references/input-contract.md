# 入力契約

制作前に `marketing-brief.md` を読み、成果設計カードを作る。不明な項目を事実のように補わない。

- 商品名、商品タイプ、LP目的、CTA URL
- 読者、実際の利用者、購入・申込の決裁者
- 支払者、LPを見る直前の状況、購入障壁
- 読者の現在の困りごと、望む変化、購入直後、商品体験後、保証しない変化
- ファネル上の役割、流入元、動かすKPI、計測イベント、判定時期、改善基準
- 商品で実際に見せられる中身・画面・実物・一場面
- 証明できる事実、禁止したい主張、期限と期限の出典
- 既存キャラクターやブランドの参照画像と利用権
- 広告主が所有または使用許諾を得た名称の一覧、第三者標章がないことの確認記録
- ページ数、販売圧、販売ストーリーの手動指定（任意）

CTA URLや根拠が未確定なら、プレースホルダーで公開用 `finalize` を通さない。期限は出典があるときだけ記載する。

`script.json` の正本は次の要素を持つ。

- `meta.strategy`: 商品・目的・販売スタイル・読後行動
- `meta.marketing`: フェーズ、ファネル、ターゲット、購入前後の変化、KPI、仮説、根拠、計測、ルート候補、四面品質審査予定
- `meta.rights`: 許諾済み名称、第三者の名称・ロゴ・キャラクター0件、確認済みフラグ、確認根拠
- `characters`: 描写と相対参照パス
- `proof_loops`: 障壁、仕組み、使用場面、確認可能な結果
- `panels`: ページ、構造ビート、絵、人物、画像、吹き出し
- `cta`: ラベルとURL

販売スタイル別の必須ビートは `scripts/engine/strategy.py` が唯一の正本。
