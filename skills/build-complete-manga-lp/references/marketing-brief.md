# 顧客変化マーケティング・ブリーフ

漫画LPは公開物であり、制作前に「誰の・どんな変化を、どの数字で確かめるか」を宣言する。絵や物語から始めない。

## 1. フェーズとファネル

- `phase`: P0（打席前）/ P1（手動販売）/ P2（循環）
- `funnel_stage`: 認知 / 集客 / 教育 / 販売 / 定着
- `traffic_source`: どこから来た人が読むか。X、note、広告、商品ページ内などを具体化する
- `kpi`: このLPが直接動かす数字を1つに絞る

漫画LP単体へ事業全体の責任を背負わせない。認知施策なら表示後の遷移、販売施策ならCTAクリックや購入を測る。

## 2. ターゲット

年齢・性別だけで定義しない。次をすべて埋める。

- `segment`: どんな変化を望む最小の集団か
- `situation`: LPを見る直前、何が起きているか
- `desired_progress`: 本人が片づけたい用事、進めたい変化
- `user`: 実際に商品を使う人
- `decision_maker`: 購入・申込を決める人
- `payer`: お金を支払う人
- `barrier`: 購入を止める不安、反論、慣性

利用者・決裁者・支払者が違う場合は一人にまとめない。利用者の欲望と決裁者の判断材料を別々にストーリーへ置く。

## 3. 変化

- `before`: 購入前の認識・感情・行動
- `after_immediate`: CTA後または購入直後に起こす変化
- `after_experience`: 商品を体験したあとに望む具体的行動
- `non_goal`: 商品やLPが保証しないこと

「笑顔になる」「人生が変わる」では不合格。教科書を自分から開く、サンプルを一章読む、画面で一件出力する、家族へ相談する、のように絵と計測で確認できる行動へ落とす。

## 4. 成果設計カード

```text
■ 成果設計カード: <漫画LP名>
- 観測する指標:
- 変化してほしい人・行動:
- 仮説:
- 根拠: 顧客/競合/市場/実売/自分/勘、日付、出典、発見
- やらないこと:
- 審査予定: 構造・表現・事実・法務
- 計測: イベント、方法、判定時期、継続・修正・中止条件
```

根拠がなければ `勘` と明記してよい。勘を調査と偽らない。実績・数字・体験談・期限を作らない。

## 5. ストーリー・スイッチ

`auto` は推奨案を含む最大3案を提示する。各案に「誰の何を動かすか」「強み」「弱み」を一行で添える。

- ユーザーが選んだ: `confirmation = user_selected`
- 自動推奨で進めることを伝えた: `confirmation = auto_recommended`

`route_decision.presented=true`、候補2案以上、選定理由、確定方法が揃うまでネームへ進まない。手動指定はユーザーが表現を指定したときだけ使う。

## 6. ネームへの接続

- フック: `target.situation` と `before`
- 現在の困りごと: `desired_progress` を阻むもの
- 反論処理: `barrier`
- 商品体験: 仮説を目で確かめられる場面
- 達成: `after_experience` のうち商品資料で証明できる最小単位
- CTA: `after_immediate` を起こす具体的な動詞

各ビートがマーケティング・ブリーフのどの項目を動かすか説明できなければ、そのコマは削るか設計し直す。

## 7. 効果の扱い

スキルは売上を保証しない。公開前の品質ゲートと、公開後に学べる計測ループを保証する。

1. 仮説を1つ宣言する
2. 1バージョンを公開する
3. KPIを決めた期間で測る
4. 最も弱い一箇所だけ変更する
5. 採用・修正・中止を判断ログへ残す

計測計画がない漫画LPは完成品ではなく、未検証のクリエイティブである。
